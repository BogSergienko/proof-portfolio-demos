# Example 1 — CSV exports → checked orders + separate problem queue

**Synthetic shop:** two CSV exports from a storefront and point of sale.

Input: `Выгрузка_магазин.csv`, `Выгрузка_касса.csv` (UTF‑8 BOM, semicolon separated). 138 records in total.

`python process_orders.py` creates:

- `01_Проверенные_заказы.csv`: 111 records passing these illustrative rules.
- `02_Проблемные_строки.csv`: 27 rejected/flagged records, **including the reason**.
- `03_Сводка.csv`: per-category summary using a simplified paid-minus-refunded rule.
- `04_Показатели.json`: audit totals, including 14 duplicate IDs, 9 incorrect totals and 4 invalid numeric formats.

The `.xlsx` report is a **pre-generated visual example**, not regenerated by `process_orders.py`; regeneration of XLSX would require a spreadsheet library.

### Reproduce everything

`python generate_example.py` recreates the two deterministic input files (will overwrite the bundled *synthetic inputs*), then `python process_orders.py` recreates all four output files. The existing originals can be compared with the copies from the repository.

### What this does NOT promise

Not an ERP integration, not full accounting, not proof of financial benefit, not suitable to ingest real customer data without tailored rules. For example, duplicates are identified by order ID using first-seen semantics; that policy needs customer validation.
